# Cockpit Nav 走行・気象記録 データ仕様（読み取り連携用）

対象：Cockpit Nav が OneDrive に書き出す走行記録と、3か月ごとのまとめ。
外部アプリはこのデータを**読むだけ**にしてください（書き込み・削除はしない）。

- 版：記録ファイル `ver: 2`（2026-11-29〜）、まとめファイル `ver: 1`
- 実装：`index.html` の「走行と天気の記録（OneDrive に 日別・時間別）と 履歴照会」のあたり

---

## 1. フォルダの構成

OneDrive（Microsoft Graph `me/drive/root`）のパスです。

```
/Apps/CockpitNav/
├─ cockpit-nav.json                  … 裏道・お気に入りなどの同期データ（この仕様の対象外）
└─ log/
   ├─ 2026/11/29/
   │   ├─ 00-ab12.json               … 2026-11-29 00:00〜00:59（日本時間）、端末 ab12 の記録
   │   ├─ 01-ab12.json
   │   └─ 09-x7k3.json               … 別の端末（パソコンなど）の記録
   └─ summary/
       └─ 2026-Q4-ab12.json          … 2026年10〜12月の1日ごとのまとめ（端末 ab12）
```

- 年/月/日/時 は**日本時間（Asia/Tokyo）**です
- ファイル名は `時(2桁)-端末ID.json`。1端末につき1時間1ファイルです
- 四半期は Q1＝1〜3月、Q2＝4〜6月、Q3＝7〜9月、Q4＝10〜12月
- 読み取りに必要な Graph の権限は `Files.Read` だけです

## 2. 1時間ごとの記録ファイル

```json
{
  "app": "cockpit-nav-log",
  "ver": 2,
  "dev": "ab12",
  "hour": "2026-11-29/09",
  "tz": "Asia/Tokyo",
  "trk": [[1795910400, 35.68123, 139.76712, 32, 270, 18, 6, 0]],
  "wx":  [{ "t": 1795910412345, "la": 35.6812, "lo": 139.7671, "T": 12.3, "H": 64, "P": 1001,
            "wd": 248, "ws": 4.9, "wg": 8.1, "wst": "船橋", "rain": "雨 2h なし", "dew": "結露 24h 低い", "pm": 9 }]
}
```

### 2.1 `trk`：走行の点（配列の配列）

| 位置 | 名前 | 単位・内容 |
|---|---|---|
| 0 | 時刻 | UNIX秒（UTC基準）。表示は日本時間に直す |
| 1 | 緯度 | 度（WGS84、小数5桁≒1m） |
| 2 | 経度 | 度（WGS84、小数5桁） |
| 3 | 速度 | km/h（整数）。GPSの速度 |
| 4 | 方位 | 度（整数、0＝北）。画面に出している向き（コンパスとGPSの進行方向を混ぜたもの）。取り込み分は 0 |
| 5 | 高度 | m（整数）。端末が返すGPS高度で、基準面は端末によって違う。不明は null |
| 6 | 測位精度 | m（整数）。GPSの水平精度。不明は null（ver 2 から） |
| 7 | 出どころ | 0＝その場で測った値、1＝走行履歴から取り込み（5秒ごとの記録）、2＝走行履歴から取り込み（時刻と速度は推定）（ver 2 から） |

- 記録の間隔：GPSを受信している間、10秒ごとに確認して、**15m以上動いたか、前の点から60秒たったとき**に1点
- ver 1 のファイルは要素が6つ（位置0〜5）です。ver 1 には測位精度と出どころがありません
- 「走行ID」はありません。**点と点の間が600秒（10分）より空いたら別の走行**として扱っています
- デモ走行の最中は記録しません

### 2.2 `wx`：天気（10分ごと）

| 項目 | 内容 | 種類 | 取得元 |
|---|---|---|---|
| t | 時刻（UNIXミリ秒） | | |
| la, lo | 記録した場所（小数4桁≒10m） | | |
| T | 気温 ℃ | **推定**（気象モデルの現在値） | Open-Meteo Forecast API `current` |
| H | 湿度 % | 推定 | 同上 |
| P | 海面気圧 hPa | 推定 | 同上 |
| wd | 風向 度（風が吹いてくる方向、0＝北）。静穏は null | **実測** | 気象庁アメダス（いちばん近い観測点、10分値） |
| ws | 風速 m/s | 実測 | 同上 |
| wg | 最大瞬間風速 m/s（ないときは null） | 実測 | 同上 |
| wst | アメダスの観測点の名前 | | 同上 |
| rain | 「雨 2h なし」「雨 10:15〜」などの文 | **予報** | Open-Meteo 15分ごとの降水予報 |
| dew | 「結露 24h 低い」などの文 | 推定（アプリが計算） | Open-Meteo の気温・露点 |
| pm | PM2.5 µg/m³ | 推定 | Open-Meteo Air Quality API |

- 値を取れなかった項目は null です
- 履歴照会の「地図で再生」で出す当時の雨・風は、再生するときに Open-Meteo の過去の1時間値を取りにいくだけで、**ファイルには保存していません**

## 3. 3か月ごとのまとめファイル

```json
{
  "app": "cockpit-nav-sum",
  "ver": 1,
  "dev": "ab12",
  "q": "2026-Q4",
  "days": {
    "2026-11-28": { "dist": 42150, "mov": 4380, "mx": 78, "ts": 89.6, "tn": 7, "tmin": 11.2, "tmax": 14.0 }
  }
}
```

| 項目 | 内容 |
|---|---|
| days のキー | 日本時間の日付 |
| dist | 走行距離 m。前の点からの間隔が600秒未満で、かつ3000m未満の区間だけを足す |
| mov | 走行時間 秒。上の区間のうち、20m以上動いたか、速度が3km/hを超えた区間の秒数を足す |
| mx | 最高速度 km/h |
| ts, tn | 気温の合計と件数。平均気温は ts ÷ tn |
| tmin, tmax | 気温の最低と最高 |

- 走りながら足していくので、取り込みや作り直しのときは1時間ごとのファイルから計算し直します

## 4. 時刻とタイムゾーン

- `trk[0]` は UNIX秒、`wx.t` は UNIXミリ秒で、どちらもUTC基準です
- フォルダ・ファイル名・`hour`・`days` のキーは日本時間です
- 例：`1795910400`（UTC 2026-11-29 00:00）は日本時間 09:00 なので `log/2026/11/29/09-xxxx.json` に入ります

## 5. 端末ID

- 端末ID（`dev`）は、アプリを入れたときに作る英数字4文字の乱数です。人やアカウントとは結びつきません
- アプリのデータを消すと、新しいIDになります
- iPhoneとパソコンなど、端末ごとに別のファイルに書くので、**ほかの端末のファイルを上書きすることはありません**

## 6. 重複・欠測・通信断

| 状況 | Cockpit Nav の動き | 読む側へのお願い |
|---|---|---|
| 同じ時間を何度も送る | 5分ごとにその時間のファイルを**丸ごと上書き**する（PUT）。同じ時刻の点は1つだけ | 最新のファイルをそのまま使う |
| 2台が同時に記録した | 端末ごとに別ファイルになる | 同じ時刻帯の点を時刻で並べて使うか、点の多い端末を選ぶ |
| 圏外・未サインイン | iPhoneに最大7日分ためて、つながったら送る | 最新の1時間は、まだ届いていないことがある |
| 送信の途中で失敗 | その時間から先は次の機会にもう一度送る | ファイルが無い時間は「記録なし」として扱う |
| サインインの期限切れ | 裏で更新する。走行中・案内中は画面を切り替えず、止まってから更新 | 遅れて届くことがある |
| 取り込み | 走行履歴の点は、すでにある点と時刻が重ならないように足す | `trk[7]` が 1 か 2 の点は、あとから取り込んだもの |

## 7. 版の管理

- 各ファイルの `app` と `ver` で見分けます
- 項目を増やすときは、配列なら**後ろに足す**、オブジェクトなら新しいキーを足します。読む側は、知らない項目を無視してください
- 意味を変えるときだけ `ver` を上げて、この文書に書きます

## 8. 汚染の写真との結び付け方（例：撮影の72時間前まで）

1. 写真の撮影時刻（日本時間）から、さかのぼる時間（24・48・72時間）を決める
2. その範囲の日付ごとに `log/年/月/日` の一覧を取り、`時-*.json` を全部読む
3. `trk` を時刻で並べて、範囲内の点だけ残す（600秒より空いたところで走行を分ける）
4. `wx` を同じ範囲で並べる。T/H/P は推定、wd/ws は実測、rain は予報として区別して扱う
5. 当時の降水量を細かく見たいときは、Open-Meteo の過去の1時間値（Historical Forecast API）を走った経路のまわりで取る
